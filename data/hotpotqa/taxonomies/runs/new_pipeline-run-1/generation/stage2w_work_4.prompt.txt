      produced by the environment, not by an agent.

  `===== TURN k · agent: NAME =====` ... `===== end of turn k =====`
      One agent turn, holding three sections in this order:
        `--- instructions given to this agent ---`   the agent's own instructions
        `--- input this agent received ---`          what it was handed
        `--- output this agent produced ---`         what it produced

  `===== OUTPUT WITHOUT PRECEDING INSTRUCTIONS ... =====`
      Assembled by the harness. Not a turn.

A turn is judged against ITS OWN instructions section and ITS OWN input
section, and nothing else. Instructions shown in another turn do not bind this
one, even when the agent has the same name in another trace. A mistake already
present in a turn's input belongs to the earlier turn that produced it, not to
this one.

# Instructions for Second-Hop Query Generation

## Task Description
You are a key component of a multi-hop information retrieval system. The system answers complex multi-hop questions using a two-stage (two-hop) retrieval process:
1. **First Hop:** Standard retrieval using the user's original question produces initial document summaries (`summary_1`).
2. **Second Hop (Your Task):** Using the original `question` and the information retrieved in `summary_1`, generate a targeted search `query` to retrieve the remaining missing documents required to fully answer the question.

---

## Input Format
- `question`: The original multi-hop question.
- `summary_1`: A summary of documents retrieved during the first hop. Each summary entry lists the document title and a summary of its contents.

---

## Output Format
Your output must contain two fields:

1. `reasoning`: A step-by-step analysis explaining:
   - What facts or entities are already provided in `summary_1`.
   - What specific missing information (entities, relationships, facts) is still needed to answer the question.
   - How the proposed query will target those missing details.

2. `query`: A search query optimized for an information retrieval system (e.g., search engine or document retriever).

---

## Query Generation Rules & Guidelines

1. **Generate a Search Query, NOT an Answer:**
   - **Do NOT** output the final answer to the question as the query.
   - **Do NOT** output conversational statements or complete explanations.
   - The query will be fed directly into a search index to retrieve additional documents.

2. **Focus on Missing "Bridge" Entities and Relationships:**
   - Identify the missing connection between the first-hop facts and the final answer.
   - For example, if the question asks about "the actress in Movie X who appeared in a comic book movie," and `summary_1` does not mention the actress's name, your query should explicitly search for the cast or lead actress of "Movie X".

3. **Query Optimization Strategy:**
   - **Use Specific Entities & Keywords:** Combine specific titles, named entities, and key terms extracted from the original question or `summary_1`.
   - **Keep it Focused:** Avoid overly long or convoluted natural language questions that might degrade retrieval performance. Focus on core entities and terms (e.g., `Enemies Among Us film cast actress comic book movie`).
   - **Adapt to Hop 1 Gaps:** If Hop 1 failed to retrieve information about a key entity in the question, phrase the query to explicitly surface that specific entity or its cast/details.

---

[Step-by-step analysis identifying what is known from summary_1, what bridge information is missing, and how to query for the missing entities/documents]

comparison, an inference, an application of a rule or definition, a judgement
about the material, a decision about what to do next, a choice of what to
carry forward.

THE FIRST STEP OF EVERY TURN IS INTAKE. Before anything else, check what the
agent took from its own input section. Did it read the task correctly? Did it
