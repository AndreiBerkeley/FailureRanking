## HOW THE TRACES ARE LAID OUT

Each trace is a sequence of blocks.

  `===== ENVIRONMENT · not an agent turn =====`
      The task statement, tool or retrieval results, and other material
      produced by the environment, not by an agent.

  `===== TURN k · agent: NAME =====` ... `===== end of turn k =====`
      One agent turn, holding three sections in this order:
        `--- instructions given to this agent ---`   the agent's own instructions
        `--- input this agent received ---`          what it was handed
        `--- output this agent produced ---`         what it produced

  `===== OUTPUT WITHOUT PRECEDING INSTRUCTIONS ... =====`
      Assembled by the harness. Not a turn.

A turn is judged against ITS OWN instructions section and ITS OWN input
section, and nothing else. Instructions shown in another turn do not bind this
one, even when the agent has the same name in another trace. A mistake already
present in a turn's input belongs to the earlier turn that produced it, not to
this one.

### Step-by-Step Guide to Deploying Python on Cloud Run

#### 1. Prepare your Application
*   **Requirements:** Ensure you have a `requirements.txt` file listing all dependencies.
*   **Web Server:** Use a production-grade WSGI/ASGI server like `gunicorn` (for Flask/Django) or `uvicorn` (for FastAPI). Do not use the built-in development server (e.g., `app.run()`).

#### 2. Create the Dockerfile
Use a lightweight base image like `python:3.11-slim`.
```dockerfile
# Use a lightweight base
FROM python:3.11-slim

# Set working directory
WORKDIR /app

# Prevent Python from writing pyc files and enable unbuffered logging
ENV PYTHONDONTWRITEBYTECODE=1
ENV PYTHONUNBUFFERED=1

# Install dependencies
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Copy application code
COPY . .

# Create a non-root user for security
RUN adduser --disabled-password appuser
USER appuser

# Start the app (Cloud Run provides the PORT env var)
CMD exec gunicorn --bind :$PORT --workers 1 --threads 8 --timeout 0 main:app
```

#### 3. Build and Push
1.  **Build:** `docker build -t gcr.io/[PROJECT_ID]/[APP_NAME] .`
2.  **Push:** `docker push gcr.io/[PROJECT_ID]/[APP_NAME]`

#### 4. Deploy to Cloud Run
`gcloud run deploy [SERVICE_NAME] --image gcr.io/[PROJECT_ID]/[APP_NAME] --platform managed --region [REGION]`

### Exemplary Practices & Enhancement Strategies
*   **Multi-Stage Builds:** Use a builder stage to compile dependencies and a final runtime stage to keep the image size small.

*   **Environment Variables:** Use Google Secret Manager for sensitive keys instead of hardcoding them.
*   **Logging:** Always write to `stdout` and `stderr` so Cloud Logging can automatically capture your application logs.

### Potential Pitfalls

*   **Timeout Issues:** If your container takes too long to respond to the initial health check, Cloud Run will kill it. Adjust the startup CPU boost or optimize your initialization logic.
*   **Heavy Images:** Avoid installing compilers (like `gcc`) in the final runtime layer unless strictly necessary, as they increase attack surface and image pull times.
