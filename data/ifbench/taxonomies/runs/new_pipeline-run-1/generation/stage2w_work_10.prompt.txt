present in a turn's input belongs to the earlier turn that produced it, not to
this one.

### 2. Technical Guidance (Deploying Python Web Apps to Google Cloud Run)
When providing step-by-step guides for deploying Python applications to Cloud Run via Docker:
* **Networking & Port Binding:**
  * Cloud Run expects containers to listen on network address `0.0.0.0` (never `127.0.0.1`/`localhost`).
  * The application must bind to the port defined by the `PORT` environment variable (defaulting to `8080`).
* **Production Web Servers:**
  * Use WSGI/ASGI production servers such as Gunicorn or Uvicorn in the Dockerfile `CMD` (e.g., `exec gunicorn --bind :$PORT --workers 1 --threads 8 --timeout 0 main:app`).
* **Build & Deployment Workflow:**
  1. **Artifact Registry:** Create a Docker repository via `gcloud artifacts repositories create`.
  2. **Build:** Submit build using `gcloud builds submit --tag REGION-docker.pkg.dev/PROJECT_ID/REPO_NAME/IMAGE_NAME`.
  3. **Deploy:** Deploy service using `gcloud run deploy SERVICE_NAME --image REGION-docker.pkg.dev/PROJECT_ID/REPO_NAME/IMAGE_NAME --platform managed --region REGION --allow-unauthenticated`.
* **Best Practices & Pitfalls to Highlight:**
  * *Base Images:* Use `python:3.11-slim` or `alpine` to reduce image size and minimize cold start times.
  * *Multi-Stage Builds:* Use builder stages to keep final production images minimal.
  * *Security:* Avoid running containers as root. Add a non-root user (e.g., `RUN adduser --disabled-password appuser` and `USER appuser`).
  * *Secrets Management:* Never hardcode API keys or secrets in Dockerfiles; inject them using **Google Secret Manager**.
  * *Resource Management:* Monitor RAM usage to prevent "OOM Killed" crashes (adjust Cloud Run `--memory` settings if needed).
