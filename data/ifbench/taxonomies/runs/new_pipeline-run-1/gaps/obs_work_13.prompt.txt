Each trace is a sequence of blocks.

  `===== ENVIRONMENT · not an agent turn =====`
      The task statement, tool or retrieval results, and other material
      produced by the environment, not by an agent.

  `===== TURN k · agent: NAME =====` ... `===== end of turn k =====`
      One agent turn, holding three sections in this order:
        `--- instructions given to this agent ---`   the agent's own instructions
        `--- input this agent received ---`          what it was handed
        `--- output this agent produced ---`         what it produced

  `===== OUTPUT WITHOUT PRECEDING INSTRUCTIONS ... =====`
      Assembled by the harness. Not a turn.

A turn is judged against ITS OWN instructions section and ITS OWN input
section, and nothing else. Instructions shown in another turn do not bind this
one, even when the agent has the same name in another trace. A mistake already
present in a turn's input belongs to the earlier turn that produced it, not to
this one.

* **Age Discrimination in Employment Act (ADEA) of 1967:**
  * Under U.S. federal law, it is strictly illegal to discriminate against job applicants or employees who are **40 years of age or older** based on age in hiring, discharge, compensation, or terms/conditions of employment.
* **Refusal Protocol:**

### 2. Technical Guidance (Deploying Python Web Apps to Google Cloud Run)
When providing step-by-step guides for deploying Python applications to Cloud Run via Docker:
* **Networking & Port Binding:**
  * Cloud Run containers must listen on network address `0.0.0.0` (never `127.0.0.1` or `localhost`).
  * The application must bind dynamically to the port defined by the `PORT` environment variable (defaulting to `8080`).
* **Production Web Servers:**
  * Use WSGI/ASGI production servers such as Gunicorn or Uvicorn in the Dockerfile `CMD` (e.g., `exec gunicorn --bind :$PORT --workers 1 --threads 8 --timeout 0 main:app`).
* **Build & Deployment Workflow:**
  1. **Artifact Registry:** Create a Docker repository using `gcloud artifacts repositories create`.
  2. **Build:** Submit build using `gcloud builds submit --tag REGION-docker.pkg.dev/PROJECT_ID/REPO_NAME/IMAGE_NAME`.
  3. **Deploy:** Deploy service using `gcloud run deploy SERVICE_NAME --image REGION-docker.pkg.dev/PROJECT_ID/REPO_NAME/IMAGE_NAME --platform managed --region REGION --allow-unauthenticated`.
* **Best Practices & Security:**
  * *Base Images:* Use minimal base images like `python:3.11-slim` or `alpine` to reduce image size and minimize cold start times.
  * *Multi-Stage Builds:* Use builder stages to keep final production images clean and minimal.
  * *Security:* Avoid running containers as `root`. Create and switch to a non-root user (e.g., `RUN adduser --disabled-password appuser` and `USER appuser`).
  * *Secrets Management:* Never hardcode API keys or credentials in Dockerfiles; inject them securely using **Google Secret Manager**.
  * *Resource Management:* Monitor RAM usage to prevent "OOM Killed" (Out Of Memory) crashes; adjust Cloud Run `--memory` settings as needed.

## Key Compliance & Formatting Rules

### 1. Verbatim Prompt Repetition Instruction
When a query asks to repeat the request word-for-word before providing the answer (e.g., *"First repeat the request word for word without change, then give your answer..."*):

- **Exclusion Rule**: Exclude the meta-instruction sentence itself (e.g., `(1. do not say any words or characters... 2. the request you need to repeat does not include this sentence)`) from the text being repeated.
- **Exact Punctuation & Spelling Preservation**: The repeated text must match the specified query segment **100% verbatim**, preserving all original punctuation, capitalization, and words. Do not alter, omit, or edit punctuation (e.g., removing commas to satisfy a separate negative constraint) within the repeated prompt text.

### 2. Output Formatting & Structural Constraints
- **Sentence Count Constraints**: If a minimum sentence count is required (e.g., "at least 4 sentences"), ensure the body of the response strictly satisfies or exceeds the minimum sentence threshold.
- **Negative & Word Frequency Constraints**: Strictly honor rules restricting specific words or characters (e.g., "the word 'section' should appear less than 2 times" or "refrain from using any commas"). - **Bullet Points & List Styling**: Follow exact bullet point count limits or character markers (`*`, `-`, numbers) whenever specified.

## Technical & Domain Guidelines

### Mathematical & Revenue Calculation Word Problems
- **Revenue Aggregation**:
  - Calculate updated time allocations: $H_{\text{new}} = H_{\text{base}} \times \text{multiplier}$ or $H_{\text{base}} - \text{offset}$.
  - Calculate revenue per category: $\text{Revenue}_i = H_{\text{new}, i} \times \text{Rate}_i$.
  - Sum for total revenue: $\text{Total Revenue} = \sum \text{Revenue}_i$.
  - *Example*: 
    - Indie: $30 \text{ hrs} \times 2 = 60 \text{ hrs}$; $60 \times \$20 = \$1200$.
    - Commercial: $45 \text{ hrs} - 10 = 35 \text{ hrs}$; $35 \times \$35 = \$1225$.
    - Total = $\$1200 + \$1225 = \$2425$.

### JavaScript / Code Refactoring (DRY Principle)
- When refactoring code to adhere to the "Don't Repeat Yourself" (DRY) principle:
  - Store repetitive scalar variables in structured objects or arrays.
  - Use programmatic aggregation functions (e.g., `Object.values().reduce()`) instead of manual addition to ensure scalability.

### Mathematical Analysis (Consecutive Integer Problems)
- When evaluating modular/integer constraints for sequences of $n$ consecutive numbers summing to a constant $S$:
  - **Consecutive Integers**: $n x + \frac{n(n-1)}{2} = S \implies n x = S - \frac{n(n-1)}{2}$. Check if $n x$ is divisible by $n$.
  - **Consecutive Even/Odd Integers**: $n x + n(n-1) = S \implies n x = S - n(n-1)$. Check if $n x$ is divisible by $n$.

## TASK

Take the traces ONE AT A TIME. Within each trace, take the turns ONE AT A TIME,

Within each turn, walk through EVERY SUBSTANTIVE STEP the agent took in its
output, in order, and check each one before moving to the next. A substantive
step is any point where the agent did work: a calculation, a transformation, a
comparison, an inference, an application of a rule or definition, a judgement
about the material, a decision about what to do next, a choice of what to
carry forward.

THE FIRST STEP OF EVERY TURN IS INTAKE. Before anything else, check what the
agent took from its own input section. Did it read the task correctly? Did it
register every constraint and condition stated there? Did it parse the
material it was given without corrupting or dropping any of it? Did it carry
forward what its input established, or did it lose an entity, a fact, or a
finding that was in front of it? An agent that starts from a misreading is
wrong from that point on, however sound everything after it looks.

TAKE THE INPUT AS GIVEN AND JUDGE ONLY WHAT THE AGENT DID WITH IT. If the input
section was already wrong, acting on it is not this turn's mistake; it belongs
to the turn that produced it. If the input was right and this agent misread,
mishandled, ignored, or failed to carry forward part of it, that IS its
mistake, and it is exactly what this pass exists to catch.

RECOVERY DOES NOT EXCUSE A FAILURE. A mistake that a later turn caught, worked
around, or happened to compensate for is still a mistake and is still
reported.

For each step, in order:
  1. State what the step did, in a few words.

You are NOT checking output formatting, required sections, or whether
